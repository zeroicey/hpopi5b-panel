# 天气幕：版式 B（主城 + 底部关注城市条），数据源 Open-Meteo，天气词不用图标

**Status:** ✅ ACCEPTED · **Date:** 2026-11-09 · **Deciders:** owner（选版式 B + 指定城市）+ AI 实现/实测 · **Supersedes:** none

## Context

用户要「新一幕，天气相关的，显示最近天气，我所在的位置在广东东软学院，看看怎么设计这个 UI，需不需加多几个地区占满空位」。
已有约束：渲染路径**永不联网**（`trending` / `news` 都是「timer 抓 → 缓存 TSV → 幕只读」）；kiosk 无键鼠，
四幕轮换；CPU 与内存预算不能为这一幕破坏；真屏验收只能看像素，不能依赖图标资产（仓库里没有）。

## Options

| Option | Upside | Downside | Reversibility |
| --- | --- | --- | --- |
| A 主城单屏 + 周边小卡 | 信息密度高、实现简单 | 用户说「需不需加多几个地区占满空位」；单一主城右栏会空 | easy |
| **B 主城 + 底部关注城市条** | 主城信息完整、底部四列把「关注城市」变成常驻比分；不抢主城 | 多一行 96px 高，主城纵向少一点 | easy（删底条即 A） |
| C 多城市等权网格 | 每个城市一样大 | 广东东软学院不是「主城」；24h 曲线/七天放不下 | medium |

**用户选择：B。** 指定城市原话：「东莞市常平镇 湖北省利川市 还有位置的话就 广州 深圳」。
底条标签用 **「关注城市」**，不是「周边城市」——利川距佛山约 900 km，叫周边不诚实。

## Decision

1. **版式 B**：左栏主城 61.5%（`L_WX_MAIN_FRAC`），右栏七天预报，底部 96px 通栏「关注城市」四列
   （东莞 · 常平 / 湖北 · 利川 / 广州 / 深圳；主城不重复出现）。
2. **数据源 Open-Meteo**：免 key、免注册；5 城 × 7 天 `current` / `hourly` / `daily` + `air-quality`
   （US AQI / PM2.5 / UV）。`tools/fetch-weather.py` 由 `hpopi5b-weather.timer` 每 **10 分钟**跑，
   原子写 `/var/cache/hpopi5b-panel/weather.tsv`；`src/scene_weather.c` 只 `stat()` + 读文件。
3. **不画图标**：用 WMO code → 天气词 + 语义色（晴桃 / 阴灰 / 雨蓝 / 雪薰衣草 / 雷暴红），曲线、温度条、
   降水条承担视觉重量。理由：没有图标资产、真屏验收只能看像素、图标还会引入 theme 两套色问题。
4. **`scene_t.live = 0`**：只吃外部文件；`sig` 混 `st_mtime` / `st_size` / 城市数 / `wall/60`。
   否则 1Hz 采样快照会让天气幕也每秒整屏重绘（同 `docs/pitfalls.md` 24）。
5. **诚实数据**：缺值 `-1` 不编零；缓存 >30 分钟「N 分钟前同步」转黄；无文件空态写清
   `hpopi5b-weather.service` 和缓存路径；抓取失败保上一份。

## Consequences

- 轮换从 3 幕变 **4 幕 × 30s = 120s 一圈**，已到 `scenes.c` 注释的 2 分钟上限；再加幕需要改「告警幕常驻」策略。
- 多了 `fetch-weather.py` 要与二进制分开部署（`docs/deploy.md` ③c），漏装只会让幕停在旧缓存。
- 城市坐标写死在 `tools/fetch-weather.py` 的 `CITIES` 表；改城市不要改 C 布局。
- 主城坐标 23.1366,113.0237（佛山南海狮山南海软件科技园）；常平 22.97692,113.99024；利川 30.29649,108.93776。
- Open-Meteo 免费层无 SLA；AQ 接口挂了只写 `-1`，主预报照常。

## Revisit when

- 用户想加第 5 个关注城市 ⇒ 底部四列会挤，需要改成两行或滚动（先问，不要自动加）。
- 4 幕轮换导致值班漏看告警 ⇒ 回到「panel 常驻 + 其余轮换」的方案，不是压 `--rotate`。
- 想画天气图标 ⇒ 需要先有图标资产/字体并接受真屏像素验收方式变化；当前明确不做。
